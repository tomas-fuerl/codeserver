## Implementierungsergebnis

`Dockerfile` pinnt GitHub CLI auf `2.96.0`. Für `TARGETARCH=amd64` wird
`gh_2.96.0_linux_amd64.tar.gz`, für `TARGETARCH=arm64` entsprechend
`gh_2.96.0_linux_arm64.tar.gz` verwendet. Die offizielle Prüfsummenliste wird
zuerst gegen ihren festen GitHub-Asset-Digest und danach das gewählte Archiv
gegen genau einen gültigen Manifesteintrag geprüft. Installation und Symlink
liegen versioniert unter `/opt/github-cli/2.96.0` beziehungsweise
`/usr/local/bin/gh`; Buildprüfungen rufen `command -v gh` und `gh --version`
auf. `ENV GH_TELEMETRY=false` deaktiviert die pseudonyme GitHub-CLI-Telemetrie
als reproduzierbaren Imagevertrag und wird statisch geprüft. Der Wert ist kein
Secret; eine lokale Abweichung erfordert eine ausdrückliche
Betreiberentscheidung. GitHub-CLI-Erweiterungen können eigene Telemetrie
besitzen und müssen separat bewertet werden.

Die vorhandenen Entwickler-, Toolchain- und statischen Installationsprüfungen
erzwingen `gh` und Version `2.96.0`. Die Node.js-Beschriftung lautet jetzt
`Node.js:`. Drei vorhandene `head`-Pipelines wurden nach reproduziertem
SIGPIPE-Exit 141 durch pipefail-sicheres `sed` ersetzt; die wiederholten
Werkzeugskripttests bestanden.

Die Repositoryskripte bleiben Prüfwerkzeuge des ausgecheckten Repositorys. Da
das Dockerfile keine `COPY`- oder `ADD`-Anweisung enthält, werden sie nicht als
Dateien oder Befehle innerhalb des Containerimages vorausgesetzt.
